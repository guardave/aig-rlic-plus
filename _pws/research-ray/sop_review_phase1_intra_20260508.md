### F-01 — Episode Slug Inconsistency Between RES-ZOOM1 and the Broader Ecosystem
**Rule/section:** RES-ZOOM1 (lines 1337–1385), cross-check against VIZ-ZOOM1, episode_registry.json, VIZ-V12
**Problem:** RES-ZOOM1 (§ "Four Canonical Episodes") lists slugs as `dot_com`, `gfc`, `covid`, `rates_2022`. These conflict with:
- VIZ-ZOOM1 canonical list in VIZ SOP: `dotcom`, `gfc`, `covid`, `inflation_2022`
- VIZ-V12 registry (standards.md): `dotcom`, `gfc`, `covid`, `taper_2018`, `inflation_2022`
- `docs/schemas/history_zoom_events_registry.json`: bootstrapped with `dotcom`, `gfc`, `covid`, `taper_2018`, `inflation_2022`
- `docs/schemas/episode_registry.json` (canonical slug source for RES-HZE1): `dot_com`, `gfc`, `covid`, `rates_2022` (matches RES-ZOOM1 for credit/activity/production/volatility/sentiment but uses `rates_2022` not `inflation_2022`)

Two distinct slug namespace problems exist:
1. `dot_com` (with underscore, RES-ZOOM1 + episode_registry.json) vs `dotcom` (no underscore, VIZ-ZOOM1 + VIZ-V12 + history_zoom_events_registry.json). A Ray author writing `dot_com` for VIZ-V12 registry lookup will get a miss; Ace writing `dotcom` in HISTORY_ZOOM_EPISODES will fail RES-HZE1's episode_registry.json slug check.
2. `rates_2022` (RES-ZOOM1 + episode_registry.json) vs `inflation_2022` (VIZ-ZOOM1 + VIZ-V12). These are the same market event named differently across Ray's rule and Vera's rule. The pre-handoff slug-check command in RES-HZE1 (line 669) uses `episode_registry.json` as the authority — but VIZ-V12's `history_zoom_events_registry.json` is the Vera-side authority. A slug that passes RES-HZE1's check (`rates_2022` in episode_registry.json) will NOT match the chart file on disk (`history_zoom_inflation_2022.json` generated by VIZ-ZOOM1) because Vera generates under her slug namespace.

**Severity proposal:** FAIL (blocking). Two agents operating on the same episode will produce incompatible slugs across the pipeline, causing silent section absence or slug-mismatch failures.
**Suggested fix:** Phase 4 — align episode_registry.json and RES-ZOOM1 to use the same slugs as VIZ-V12/history_zoom_events_registry.json (`dotcom`, `inflation_2022`), or vice versa. Lead must arbitrate. Document the canonical authority (single source of truth) in team-coordination.md. Update RES-ZOOM1, RES-HZE1 verification command, and episode_registry.json in the same commit.

### F-04 — RES-CP2 Trigger Condition Conflicts With ECON-CP2
**Rule/section:** RES-CP2 (line 1303) vs. ECON-CP2 in econometrics-agent-sop.md
**Problem:** RES-CP2 states it "triggers only when ECON-CP2 output files are present in `results/{pair_id}/`." ECON-CP2 (econometrics SOP) states it runs "conditional on `regime_story: true` in `signal_scope.json`." These are different trigger conditions:
- Ray's check: file presence in `results/{pair_id}/` (post-hoc, file-system check)
- Evan's check: `regime_story: true` in `signal_scope.json` (pre-analysis, config check)

A pair where Evan ran ECON-CP2 (regime_story=true) but the output files have not yet landed when Ray starts work will cause Ray to skip RES-CP2 narrative incorrectly. Conversely, Ray cannot independently determine whether ECON-CP2 is expected vs. a missing artifact. The trigger condition should be identical across both SOPs or explicitly stated as "Ray reads `signal_scope.json` regime_story flag" to be self-contained.
**Severity proposal:** WARN (non-blocking gap). Causes silent narrative omission in certain pipeline timings but does not produce a fatal error.
**Suggested fix:** Phase 4 — Update RES-CP2 trigger to: "triggers when ECON-CP2 output files are present in `results/{pair_id}/` OR when `results/{pair_id}/signal_scope.json` has `regime_story: true` (per ECON-CP2 trigger). If regime_story is true but files are absent, escalate to Evan before proceeding." Add a gate item in Quality Gates: "If `regime_story: true`, confirm ECON-CP2 output files present before skipping RES-CP2."

### F-05 — RES-ZOOM1 and RES-HZE1 Overlap Without Clear Boundary
**Rule/section:** RES-HZE1 (lines 620–681), RES-ZOOM1 (lines 1337–1385)
**Problem:** Both rules govern Ray's narrative authorship for historical zoom episodes in pair configs. They use different config attribute names for what appears to be the same thing:
- RES-HZE1: `HISTORY_ZOOM_EPISODES` (a `list[dict]` with keys `slug`, `title`, `narrative`, `caption`)
- RES-ZOOM1: `ZOOM_EPISODE_NARRATIVES` (a `dict` keyed by episode slug, values are narrative strings)

ACE-HZE1 (AppDev SOP) references and requires `HISTORY_ZOOM_EPISODES` only. `ZOOM_EPISODE_NARRATIVES` appears only in RES-ZOOM1 and does not appear to be consumed anywhere in the AppDev SOP or the rendered template. This creates ambiguity: which config attribute does Ray actually write? Does `ZOOM_EPISODE_NARRATIVES` still exist as a live contract, or is it superseded by `HISTORY_ZOOM_EPISODES`?

If `ZOOM_EPISODE_NARRATIVES` is retired/superseded, RES-ZOOM1's delivery format section is stale. If both are live, the SOP must clarify which is used on which page and by which template.
**Severity proposal:** FAIL (blocking). A Ray author reading both rules will author conflicting data structures. Ace's template reads `HISTORY_ZOOM_EPISODES` (per ACE-HZE1) — a Ray author who follows RES-ZOOM1 alone will produce `ZOOM_EPISODE_NARRATIVES`, which will be silently ignored.
**Suggested fix:** Phase 4 — Clarify whether RES-ZOOM1 predates RES-HZE1. If RES-HZE1 supersedes RES-ZOOM1's delivery format, update RES-ZOOM1 to say "see RES-HZE1 for the config delivery format; this rule governs content requirements per episode." If both live simultaneously (different data structures for different pages), label explicitly which page/template each feeds.

## Strengths Worth Preserving

1. **RES-OD1 three-step vocabulary+equality+direction_consistent script** — the structured Python script with explicit canonical vocabulary set `{procyclical, countercyclical, mixed}` and three ordered assertions is excellent. It is self-documenting and unambiguous about what passes vs. fails.

5. **RES-EGL1 evidence-grade verb taxonomy** — the mapping of evidence strength to permitted language (schema-validated → "durable evidence"; search-grade → "suggests") is rigorous and prevents promotional language from slipping through. The investment-language ceiling is well-defined.

7. **RES-20 episode triad definition** — "long-lead + coincident + failure-case" is a disciplined and honest framework that builds reader trust. The failure-case requirement is particularly strong; it institutionalizes intellectual honesty.

8. **Defense 1 / Defense 2 structure** — the producer-side and consumer-side defense framing is conceptually clean and creates a natural mental model for quality responsibility.
